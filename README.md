# Проект: Умный планировщик задач

## Запуск проекта:
1. Запуск Task Service (Порт 8001): `python -m uvicorn task_service.main:app --port 8001 --reload`
2. Запуск Notification Service (Порт 8002): `python -m uvicorn notification_service.main:app --port 8002 --reload`
3. `http://127.0.0.1:8001`

# Описание проекта: «Умный планировщик задач»

Это простая система для управления списком задач. Проект сделан на Python и разделен на две части, которые работают отдельно, но общаются друг с другом по сети.

## Что использовалось (Технологии)
* Python — основной язык программирования, на котором написан весь код.
* FastAPI — библиотека, которая помогла быстро запустить сервера и настроить их работу.
* Uvicorn — программа, которая запускает наши сервера в Windows.
* HTTPX — специальный инструмент внутри кода, который помогает первому сервису отправлять сообщения второму.
* HTML и CSS — на них сделана красивая веб-страница с кнопками, которую видит пользователь в браузере.

---

## Как устроена программа (Из каких частей состоит)
Проект разбит на две папки — это два независимых сервиса (микросервиса):

### 1. Сервис задач (task_service) — Работает на порту 8001
Это «сердце» нашей программы. Он делает всю основную работу и показывает пользователю сайт.

**Что он умеет делать:**
* Показывает удобный сайт в браузере: Обычный пользователь заходит на страницу http://127.0.0.1:8001 и видит форму. Там можно написать название задачи, её описание и нажать кнопку.
* Управляет задачами: Он умеет создавать задачи, показывать их списком, менять их статус (например, переводить в «В работе» или «Выполнено») и полностью удалять.
* Заполняет скрытые поля: Сам придумывает каждой задаче длинный уникальный ID (номер) и записывает точное время, когда её создали.
* Хранит данные в памяти: Все задачи сохраняются прямо в оперативной памяти. Если перезапустить сервер, список очистится. Для учебного проекта это самый быстрый и удобный вариант.
* Отправляет уведомления: Как только пользователь создает задачу, этот сервис берет её данные и мгновенно пересылает по сети второму сервису.

### 2. Сервис уведомлений (notification_service) — Работает на порту 8002
Этот сервис работает «на фоне». У него нет своего сайта, он просто сидит и ждет сообщений от первого сервиса.

**Что он умеет делать:**
* Принимает сообщения: Он постоянно слушает свой порт 8002. Как только первый сервис присылает ему данные о новой задаче, он их принимает.
* Проверяет данные: Сервис следит, чтобы присланная задача была правильной (чтобы у неё обязательно было название, текст и статус).
* Показывает красивое оповещение: Когда задача пришла, сервис выводит в терминал VS Code аккуратную рамку с текстом ПОЛУЧЕНО НОВОЕ УВЕДОМЛЕНИЕ О ЗАДАЧЕ!. В реальной жизни вместо этого лога уходила бы СМС-ка на телефон пользователю.

## Что будет, если одна часть сломается? (Отказоустойчивость)
Мы настроили программу так, что если сервис уведомлений (порт 8002) вдруг выключится или зависнет, основной сайт с задачами (порт 8001) не упадёт.

Сайт просто напишет в терминал ошибку, что не смог отправить уведомление, но саму задачу для пользователя успешно создаст и покажет на экране. Программа не сломается полностью из-за сбоя в одной её части.
